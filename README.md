# 업비트 변동성 돌파 자동매매

`trader.py` 는 업비트 원화 마켓에서 **변동성 돌파** 조건이 맞으면 시장가 매수하고, 익절·손절 또는 다음 날 09:00(KST)에 봇이 산 수량을 시장가 매도합니다. 기본 실행은 모의매매입니다.

## 전략

| 항목 | 기본값 |
| --- | --- |
| 대상 | 업비트 원화 마켓 전체 |
| 매수 | 현재가 >= 당일 시가 + (전일 고가 - 전일 저가) × 0.5 |
| 투자금 | 원화의 50%를 최대 10종목에 나눔 (종목당 5%, 거래일·종목당 1회) |
| 매도 | 익절 +3%, 손절 -2%, 또는 다음 거래일 09:00 전량 |
| 장 기준 | 업비트 일봉과 같이 한국시간 09:00 |

08:55~09:00 에는 사지 않습니다. 바로 09:00 청산과 겹치기 때문입니다. `UPBIT_NO_BUY_MINUTES=0` 이면 이 제한이 없어집니다.

봇은 자신이 기록한 수량만 팝니다. 그 전에 계좌에 있던 코인은 매도 대상이 아닙니다.

## 설치

```bash
pip install pyupbit
```

또는

```bash
pip install -r requirements.txt
```

Python 3.9 이상이 필요합니다. `pyupbit` 가 `pandas` 를 함께 설치합니다.

## 키 설정

액세스 키와 시크릿 키는 `trader.py` 안의 `ACCESS_KEY`, `SECRET_KEY` 변수가 환경 변수에서 읽습니다. 코드에 키를 붙여 넣지 마세요.

```bash
export UPBIT_ACCESS_KEY="발급받은 액세스 키"
export UPBIT_SECRET_KEY="발급받은 시크릿 키"
```

업비트 Open API 키는 **자산 조회와 주문**만 허용하고, 출금 권한은 끄세요. 키를 만들 때 등록한 IP가 아니면 업비트가 잔고 조회를 거절하고 카카오톡으로 "Open API 미등록 IP 접근" 안내를 보냅니다. Open API 관리에서 그 안내에 적힌 IP를 허용 목록에 추가한 뒤 `--live` 를 다시 실행하세요. 예시 값은 `.env.example` 에 있습니다.

## 실행

```bash
python trader.py --once    # 모의매매로 한 번만 판단
python trader.py           # 모의매매를 계속 실행 (Ctrl+C 로 종료)
python trader.py --live    # 실제 주문
```

`python` 이 없으면 `python3` 로 같은 명령을 실행하면 됩니다.

Windows에서는 `C:\Users\ksw\trade` 처럼 프로젝트 폴더를 연 뒤, 가상환경을 먼저 만듭니다. `install` 만 치거나 `.venv` 를 만들기 전에 pip 경로를 실행하면 명령을 찾지 못합니다.

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
set UPBIT_ACCESS_KEY=발급받은액세스
set UPBIT_SECRET_KEY=발급받은시크릿
.venv\Scripts\python trader.py --live
```

`python` 이 없으면 첫 줄을 `py -3 -m venv .venv` 로 바꿉니다. 실주문은 이 PC의 공인 IP가 업비트 허용 목록에 있을 때만 됩니다.

실거래는 `--live` 이거나 `UPBIT_DRY_RUN=0` 일 때만 나갑니다. 포지션은 `state/paper_KRW-ALL.json`, 시세 스냅샷은 `state/prices_paper_KRW-ALL.json` 에 저장됩니다.

한 종목만 보려면 그 종목에 원화의 50%를 씁니다.

```bash
python trader.py --ticker KRW-BTC --once
```

처음 실행하면 원화 마켓 전체의 일봉을 모읍니다. 종목이 약 300개라 1분 안팎이 걸리고, `일봉 수집 20/292` 처럼 진행이 출력됩니다. 그 다음부터는 현재가만 묶어서 조회합니다.

## 로그

매매를 시도할 때 종목, 잔고, 주문 금액, 성공/실패가 터미널에 출력됩니다. 주문이 없는 동안에는 약 60초마다 조회한 종목 수와 돌파 종목을 출력합니다.

```text
[2026-10-07 10:00:01] 시세 포착 | 조회 292개 | 돌파 4개 | 보유 0개 | 원화 1,000,000 KRW
[2026-10-07 10:00:01] 돌파 | KRW-ETH | 현재가 3,500,000 | 목표가 3,400,000 | 초과 +2.94%
[2026-10-07 10:00:01] 잔고 조회 | 원화 1,000,000 KRW | ETH 0.00000000
[2026-10-07 10:00:01] 매수 시도 | KRW-ETH | ... | 주문금액 50,000 KRW
[2026-10-07 10:00:01] 주문 성공 | 모의 매수 성공 | KRW-ETH | ...
```

시세·주문 요청 사이에는 `time.sleep(0.12)` 가 있습니다. 일봉은 여러 종목을 동시에 받되 요청 시작 간격을 그 시간으로 맞춥니다. 조회가 실패해도 프로세스는 종료되지 않고 오류를 출력한 뒤 다음 루프를 돕니다.

## 테스트

```bash
python -m unittest discover -s tests -t .
```

단위 테스트는 업비트에 접속하지 않습니다. `--once` 모의매매만 실제 시세를 조회합니다.

## 주의

이 프로그램은 전략을 코드로 옮긴 예시입니다. 암호화폐 거래는 원금 손실이 날 수 있고, 수수료·슬리피지·지연 때문에 같은 조건이라도 결과가 달라집니다. 실주문을 켜기 전에 `--once` 와 모의매매로 로그를 확인하세요.
